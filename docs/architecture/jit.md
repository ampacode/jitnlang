# Mini-JIT "anti nlang" (src/jit.cpp, src/jit_rt.cpp)

## Идея

Интерпретатор — это уже скомпилированная программа. Значит,
чтобы получить «родную» скорость, не нужен полноценный
компилятор: достаточно эмитить вызовы **тех же самых
рантайм-хелперов**, которые использует интерпретатор —
и вставлять их в машинный код на лету, мимо g++ и временных
файлов.

JIT компилирует функцию лениво — при первом вызове
(`NObject::call`, `jit_state == 0`). Нетintable-функции
остаются интерпретируемыми (`jit_state == -1`).

## Три домена значений

| Домен | Представление | Где живёт |
|---|---|---|
| `Int` | `int64` в `rax` | слоты кадра = int64 |
| `Dbl` | `double` в `xmm0` | слоты кадра = 8 байт (биты double) |
| `Obj` | `NObject*` в `rax` | слот кадра = полноценный `NObject` (56 байт, init/dtor) |

Конверсии: `int_to_obj`/`obj_to_int`,
`dbl_to_obj`/`obj_to_dbl` (`nl_jit_of_dbl`/`to_dbl`),
`int_to_dbl` = `cvtsi2sd`, `dbl_to_int` = `cvttsd2si`
(усечение, как `asInt()`).

`/` — всегда fp-деление (`cvtsi2sd`+`divsd` с проверкой
нуля через `nl_jit_div_zero`), как eval-семантика.
`%` на dbl — `nl_jit_fmod`. `x op= dbl` на int-var —
промоушен в dbl-домен (`dset`), как eval продвигает тип.
Явный `double x = ...` — сразу dbl-домен.

## Быстрый путь списков

Оффсеты варианта не хардкодятся: `nl_jit_layout_*`
пробники замеряют layout в рантайме (ll-пейлоад по
маркеру, дискриминант — байт, равный `index()` во всех
образцах, `_this`/`sizeof` — offsetof/sizeof).

- `v.push(int)` на obj-варе: `finish < endcap` проверка
  и inline-init `NObject(int)` (payload+index+нулевой
  `_this`) прямо в хвост вектора; `nl_jit_list_push_ll`
  — только при росте capacity.
- `for (x : v)` где `v` — `vector<int>`/`vector<ll>`:
  `nl_jit_list_data` берёт `data()` один раз, `x`
  объявляется int-варом, элемент читается как
  `data[i].payload` после проверки байта-дискриминанта.
  Элемент не-int → медленный путь `at_obj`+`to_int`
  (x остаётся int-варом — задокументированное
  расхождение на смешанном vector<int>, в eval такой
  лист не типизирован).
- Нетипизированные листы — старый путь `at_obj`.

Типы и операции, выходящие за примитивы (строки, списки,
методы, произвольные узлы AST) — объектный домен через
хелперы (`nl_jit_arith`, `nl_jit_list_*`, `nl_jit_strcat_*`).

## Сигнатура и кадр (Win64 x64)

```
long long fn(Nvm* vm, const long long* args, NObject* retobj)
```

- `rcx=vm`, `rdx=args` (int-аргументы), `r8=retobj`.
- int-результат возвращается в `rax`; объектный —
  в `*retobj` (тогда `rax=0`).

Кадр (оффсеты от `rbp`, `mov [rbp-off]` покрывает
`[rbp-off, rbp-off+8)` — ячейка живёт **ниже** off):

```
8=rbx 16=rdi 24=rsi 32=vm 40=retobj
int-слоты    с 48 (slot_of: 48, 56, ...)
int-scratch  staging + аргументы self-call
obj-регион   NObject-слоты (init в прологе, dtor в эпилоге)
argv         указатели на аргументные NObject для call_named
```

Obj-слот i: база `rbp - (obj_base + (i+1)*56)` — объект
занимает 56 байт **ниже** этого адреса (ранняя версия
писала вверх и затирала соседние слоты — главный баг,
нашёлся watchpoint'ом).

## Многопроходная компиляция и промоушен доменов

Домен переменной решается на компиляции, но eval — язык с
динамическими типами: `acc += (double)` в eval просто
меняет тип `vars["acc"]`. Jit делает то же самое —
**промоушен**: переменная, получившая obj-запись хотя бы
однажды, считается obj-доменом **с начала функции**.

Поэтому проходов три+:

1. **dry-1** — обнаруживает промоушены (oslots).
2. **dry-N (до стабилизации)** — re-dry с готовыми oslots:
   домены могли сдвинуть ветки эмиссии — повторяем, пока
   oslots не перестанет расти (монотонно => сходится).
3. **emit** — код с финальным layout.

`obj_slot()` во втором и следующих проходах пропускает
индексы, уже занятые oslots — temp-слоты воспроизводят
порядок последнего dry-прохода.

Скомпилированный через `cpp()`-путь код такой промоушен
не воспроизводит: `long long acc` — статический тип,
`acc += double` обрезается до int. Известный остаточный
разрыв eval↔compiled для динамических переменных.

Строковые литералы дописываются в конец буфера кода
(после `ret`), адреса патчатся прямо в `mov reg, imm64`.

## Вызовы

- **self-рекурсия** — прямой `call rel32` к точке входа,
  int-аргументы через scratch-массив. `fibo(28)` ~3 мс.
- **другие функции** — `nl_jit_call_named(vm, name, argv, n)`:
  имя → `vars[name].call()` — внутри уже jit→jit, потому
  что callee тоже имеет `fn->jit`. `calls(1e6)` ~1 мс.
- **методы/модули** (`time.now()`, `x.f()`) — getter из
  более чем одного звена → eval-фоллбэк всего узла.

## Escape hatch

Всё, что не умеет эмиттер, уходит обратно в интерпретатор:

- выражение → `nl_jit_eval_obj(vm, node, out)` /
  `nl_jit_eval_int`;
- оператор → `nl_jit_exec_stmt(vm, node)` → коды
  `0=norm, 1=return, 2=break, 3=continue, 4=error`.

Перед вызовом делается **sync-out**: все jit-слоты
сливаются в `vm.vars` (интерпретатор видит то же
состояние). После — **sync-in**: слоты перечитываются
(интерпретатор мог поменять значения). Внутренние
`@fe_*`-переменные не синхронизируются.

## Исключения

C++-исключения не могут размотаться через jit-кадр
(нет .pdata-unwind-таблиц). Поэтому хелперы ловят
`std::exception` и кладут сообщение в
`vm->pending_error`; `NObject::call` после возврата
из jit-кода перевбрасывает его как `NLangError`.
`NLangError` не наследует `std::exception` — но он и не
должен доходить до хелперов: `exec_stmt` ловит
`Break`/`Continue` отдельно.

## Эпилог и rax

`rax` с возвращаемым int спасается в `VM_SLOT` **до**
dtor-цикла obj-слотов — хелперы возвращают значения в
`rax` и затёрли бы результат (второй найденный баг:
`g()` с объектными локалями возвращала мусор).

## Отладка

- `NLANG_JIT_DEBUG=1` — дамп байткода, layout, маркеры
  helper-вызовов и pending_error.
- `NLANG_NO_JIT=1` — отключить jit (чистый интерпретатор).
- `NLANG_JIT_ONLY=substr` — jit только функций, чьи имена
  содержат подстроку (биссект по функциям).

## Скорость (bench.nlc, eval+jit vs g++ -O3)

| тест | eval | jit | cpp |
|---|---|---|---|
| arith(1e6) | ~550ms | 45ms | 1ms |
| calls(1e6) | ~340ms | 1ms | 0ms |
| fibo(28) | ~1400ms | 3ms | 1ms |
| strcat(1e5) | ~800ms | ~0ms | 0ms |
| lists(1e6) | ~860ms | 46ms | 2ms |
| hotloop | ~650ms | 1ms | 0ms |

`/ ` в jit следует eval-семантике (true-division):
`nl_div`/`nl_mod` в `runtime/nlrt.h` — compiled-код делит
так же (раньше был сырой C++ `l / r` — int-деление;
синхронизировано). `//` — floor-деление и в eval, и в
compiled (eval раньше усекал — исправлено под Python `//`).
